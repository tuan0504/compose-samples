Overview — How Many Styles?

There are 6 distinct theming styles across the 6 sample apps. They range from the simplest (pure Material 3) to the most complex (fully custom design system that doesn't use Material 3 colors at all).

Style 01 · JetNews
Pure Material 3
Full M3 color system, dynamic wallpaper colors on Android 12+, single Montserrat font.
⭐ Beginner
Style 02 · JetLagged
M3 + CompositionLocal Extension
Extends M3 with domain-specific health colors via CompositionLocalProvider.
⭐⭐ Intermediate
Style 03 · Jetcaster
Material Expressive + Shared Module
Shared design system module for phone, TV & Wear. Uses experimental MaterialExpressiveTheme.
⭐⭐⭐ Advanced
Style 04 · Jetchat
M3 + Glance Widget Theme
Standard M3 for the app + a separate GlanceTheme for home screen widgets.
⭐⭐ Intermediate
Style 05 · Jetsnack
Fully Custom Design System
Completely bypasses M3 colors. 11-step color ramps, gradient lists, debug Magenta trap.
⭐⭐⭐ Advanced
Style 06 · Reply
M3 + System Contrast Detection
Reads UiModeManager.contrast on Android 14+ and selects from 3 pre-defined contrast tiers.
⭐⭐ Intermediate

How it works

Kotlin · Theme.kt 
@Composable
fun JetnewsTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    content: @Composable () -> Unit
) {
    val colorScheme =
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
            // Android 12+: use wallpaper-based dynamic colors
            val context = LocalContext.current
            if (darkTheme) dynamicDarkColorScheme(context)
            else dynamicLightColorScheme(context)
        } else {
            // Older Android: hardcoded light/dark palette
            if (darkTheme) DarkColors else LightColors
        }

    MaterialTheme(
        colorScheme = colorScheme,
        shapes = JetnewsShapes,
        typography = JetnewsTypography,
        content = content,
    )
}

Pattern — 4 steps

Kotlin · Theme.kt 
// Step 1: Define domain-specific extra colors
data class JetLaggedExtraColors(
    val header     : Color = Color.Unspecified,
    val bed        : Color = Color.Unspecified,
    val sleep      : Color = Color.Unspecified,
    val heart      : Color = Color.Unspecified,
    val heartWave  : List<Color> = listOf(Color.Unspecified),
    val sleepAwake : Color = Color.Unspecified,
    val sleepDeep  : Color = Color.Unspecified,
    // ... 14 domain colors total
)

// Step 2: Create a CompositionLocal holder
val LocalExtraColors = staticCompositionLocalOf { JetLaggedExtraColors() }

// Step 3: Provide it alongside MaterialTheme
@Composable
fun JetLaggedTheme(isDarkTheme: Boolean = isSystemInDarkTheme(), ...) {
    val extraColors = if (isDarkTheme) DarkExtraColors else LightExtraColors

    CompositionLocalProvider(LocalExtraColors provides extraColors) {
        MaterialTheme(
            colorScheme = if (isDarkTheme) DarkColorScheme else LightColorScheme,
            content = content,
        )
    }
}

// Step 4: Clean access API via companion object
object JetLaggedTheme {
    val extraColors: JetLaggedExtraColors
        @Composable get() = LocalExtraColors.current
}

When to use

  • Need colors that don't fit into M3 role slots
  • Want dark/light variants for those extra colors too

MaterialExpressiveTheme + MotionScheme

Kotlin · Theme.kt (mobile) 
@OptIn(ExperimentalMaterial3ExpressiveApi::class)
@Composable
fun JetcasterTheme(dynamicColor: Boolean = false, content: @Composable () -> Unit) {
    val colorScheme = when {
        dynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S ->
            dynamicDarkColorScheme(LocalContext.current)
        else -> darkScheme  // imported from core:designsystem
    }

    MaterialExpressiveTheme(
        colorScheme  = colorScheme,
        motionScheme = MotionScheme.expressive(),  // animation spring/easing
        shapes       = JetcasterShapes,
        typography   = JetcasterTypography,
        content      = content,
    )
}
Purpose

The enterprise / multi-platform pattern. Design tokens defined once in a shared Gradle module, consumed by phone, TV, and Wear targets.

When to use
  • Building for multiple form factors (phone + TV + Wear + tablet)
  • Team has a shared design system across multiple modules
  • Want coordinated animation behavior via MotionScheme

App theme — dynamic color on by default

Kotlin · Themes.kt 
@Composable
fun JetchatTheme(
    isDarkTheme   : Boolean = isSystemInDarkTheme(),
    isDynamicColor: Boolean = true,  // ← enabled by default — unique to Jetchat
    content: @Composable () -> Unit
) {
    val dynamicColor = isDynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S
    val myColorScheme = when {
        dynamicColor && isDarkTheme  -> dynamicDarkColorScheme(LocalContext.current)
        dynamicColor && !isDarkTheme -> dynamicLightColorScheme(LocalContext.current)
        isDarkTheme                  -> JetchatDarkColorScheme
        else                         -> JetchatLightColorScheme
    }
    MaterialTheme(colorScheme = myColorScheme, typography = JetchatTypography, content = content)
}

Glance widget theme — separate entry point

Kotlin · widget/theme/Theme.kt 
@Composable
fun JetchatWidgetTheme(content: @Composable () -> Unit) {
    GlanceTheme(
        colors = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
            GlanceTheme.colors
        } else {
            ColorProviders(
                light = JetchatLightColorScheme,
                dark  = JetchatDarkColorScheme,
            )
        },
        content = content,
    )
}
Purpose

Maintains visual consistency between the app and its home screen widget. The widget lives outside the Compose tree and needs its own GlanceTheme entry point.

When to use
  • App ships a home screen widget via Glance API
  • Widget must visually match the app, including dynamic color

The Magenta debug trap

// All 40+ M3 slots = Magenta — any accidental usage is immediately visible
fun debugColors(darkTheme: Boolean, debugColor: Color = Color.Magenta) = ColorScheme(
    primary   = debugColor,

    secondary = debugColor,
    // ... ALL slots = Magenta

@Composable
fun JetsnackTheme(darkTheme: Boolean = isSystemInDarkTheme(), ...) {
    val colors = if (darkTheme) DarkColorPalette else LightColorPalette

    ProvideJetsnackColors(colors) {
        MaterialTheme(
            colorScheme = debugColors(darkTheme),  // ← intentional Magenta
            content     = content,

Key insight — the Magenta trick

Setting all M3 color slots to Color.Magenta is intentional. If any developer accidentally uses MaterialTheme.colorScheme.primary instead of JetsnackTheme.colors.brand, the UI turns bright pink immediately — a runtime design system boundary enforcer.

Purpose

Demonstrates a brand-first design system that completely overrides M3 colors with a proprietary 11-step palette and gradient system.

When to use
  • Brand design system is completely custom (not Material-based)
  • Need multi-stop gradient colors as first-class theme tokens
  • E-commerce, entertainment, or gaming apps with strong visual identity

Contrast-aware scheme selection

Kotlin · Theme.kt 
@Composable
fun selectSchemeForContrast(isDark: Boolean): ColorScheme {
    val uiModeManager = context.getSystemService(Context.UI_MODE_SERVICE) as UiModeManager
    val contrastLevel = uiModeManager.contrast  // Float: 0.0 → 1.0

    return when (contrastLevel) {
        in 0.0f..0.33f -> if (isDark) darkScheme                  else lightScheme
        in 0.34f..0.66f -> if (isDark) mediumContrastDarkColorScheme  else mediumContrastLightColorScheme
        in 0.67f..1.0f  -> if (isDark) highContrastDarkColorScheme    else highContrastLightColorScheme
        else           -> if (isDark) darkScheme                  else lightScheme
    }
}

Purpose

The accessibility-first pattern. Automatically adapts to the contrast level set in Android Settings → Accessibility → Color and Motion. No user action needed inside the app.

When to use
  • Government, healthcare, or public-sector apps
  • Apps targeting older users or users with visual impairments
  • Apps that must comply with WCAG 2.1 AA or AAA contrast ratios

Core Concepts to Learn First

MaterialTheme

Root of all M3 theming. Provides colorScheme, typography, and shapes to the entire composition tree below it via CompositionLocal.

CompositionLocal

Passes data implicitly through the tree without threading it through every function parameter. Used by JetLagged and Jetsnack for custom color systems.

lightColorScheme / darkColorScheme

M3 builders for color schemes. Only specify colors that differ from M3 defaults — unspecified slots get sensible baseline values automatically.

dynamicColorScheme

Android 12+ (API 31). Generates a full M3 color scheme from the user's wallpaper. Guard with Build.VERSION.SDK_INT >= Build.VERSION_CODES.S.

Minimal theme skeleton

Kotlin · starter template 
@Composable
fun MyAppTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    content: @Composable () -> Unit
) {
    val colorScheme = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
        val ctx = LocalContext.current
        if (darkTheme) dynamicDarkColorScheme(ctx) else dynamicLightColorScheme(ctx)
    } else {
        if (darkTheme) DarkColorScheme else LightColorScheme
    }

    MaterialTheme(
        colorScheme = colorScheme,
        typography  = MyTypography,
        shapes      = MyShapes,
        content     = content,
    )
}

// Access anywhere below:
val primary   = MaterialTheme.colorScheme.primary
val bodyFont  = MaterialTheme.typography.bodyLarge
val cardShape = MaterialTheme.shapes.medium

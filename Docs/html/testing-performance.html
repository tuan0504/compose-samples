02

The Two Test Rules

Choosing the wrong rule is the most common setup mistake. The choice depends on whether you own setContent.

createComposeRule — you control the composable

Use when testing an isolated screen or composable. You call setContent {} yourself.

Kotlin 
// JetLagged — no Activity context needed
class AppTest {
    @get:Rule
    val composeTestRule = createComposeRule()

    @Before
    fun setUp() {
        composeTestRule.setContent {
            JetLaggedTheme {
                JetLaggedScreen()
            }
        }
    }

    @Test
    fun app_launches() {
        composeTestRule.onNodeWithText("JetLagged").assertIsDisplayed()
    }
}

createAndroidComposeRule<Activity> — Activity owns the content

Use when testing full app navigation, or when you need activity.getString(…) for string resources.

Kotlin 
// Jetchat — needs Activity for Fragment + Navigation interop
class NavigationTest {
    @get:Rule
    val composeTestRule = createAndroidComposeRule<NavActivity>()

    @Test
    fun app_launches() {
        assertEquals(getNavController().currentDestination?.id, R.id.nav_home)
    }
}
createComposeRule createAndroidComposeRule<Activity>
Controls setContent Yes No — Activity owns it
Needs Activity class No Yes
Tests full app navigation No Yes
Isolated composable tests Yes — preferred Possible but overkill
03

The Semantic Tree

Compose tests query the accessibility semantic tree — no View IDs, no XPath. If a node isn't in the tree, the test can't find it.

Kotlin 
// Find by visible text
composeTestRule.onNodeWithText("HOME").assertIsDisplayed()

// Find by content description (icons with no visible text)
composeTestRule.onNodeWithContentDescription("Open navigation drawer").performClick()

// Find by explicit test tag — best for non-accessible nodes
composeTestRule.onNodeWithTag(ConversationTestTag).assertIsDisplayed()

// Combined matchers
composeTestRule.onNode(hasText("composers") and isInDrawer()).performClick()

// Multiple matches — pick by index
composeTestRule.onAllNodes(hasText(manuel.name, substring = true))[0]
    .performScrollTo()
    .performClick()

Expose non-accessible nodes with testTag

Kotlin 
// In your composable (production code):
const val ConversationTestTag = "ConversationTest"

LazyColumn(modifier = Modifier.testTag(ConversationTestTag)) { ... }

// In the test:
composeTestRule.onNodeWithTag(ConversationTestTag).performTouchInput {
    swipe(start = center, end = Offset(center.x, center.y + 500), durationMillis = 200)
}
Flakiness warning — useUnmergedTree
Some nodes get merged in the semantic tree for accessibility. If onNodeWithTag fails to find a node that should exist, pass useUnmergedTree = true:
composeTestRule.onNodeWithTag(tag, useUnmergedTree = true)
See issuetracker.google.com/issues/184825850

Common UI Interactions

Gestures, text input, and waiting for async content.

Click, scroll, swipe

Kotlin 
// Simple click
composeTestRule.onNodeWithText("Chips").performClick()

// Scroll to item in LazyColumn, then click
composeTestRule.onAllNodes(hasText(name, substring = true))[0]
    .performScrollTo()
    .performClick()

// Swipe gesture (reveals "jump to bottom" button)
composeTestRule.onNodeWithTag(ConversationTestTag).performTouchInput {
    swipe(
        start = center,
        end = Offset(center.x, center.y + 500),
        durationMillis = 200,
    )
}

Text input

Kotlin 
// Type into a text field
findTextInputField().performTextInput("Some text")

// Verify send button becomes enabled
findSendButton().assertIsEnabled()

Waiting for async content

Kotlin 
// Block until exactly one node with this text appears
composeTestRule.waitUntilExactlyOneExists(
    hasText("Use Dagger in Kotlin!", substring = true),
    5000L  // timeout in ms
)

// Block until at least one match appears
composeTestRule.waitUntilAtLeastOneExists(hasText("Topics"), 5000L)
Why waitUntil*?
Navigation and async data loading mean content doesn't appear instantly. These APIs block until the predicate is true or the timeout expires — avoiding flakiness from race conditions without arbitrary Thread.sleep() calls.
05

Snackbar Testing with snapshotFlow

JetNews — verifying a SnackbarHostState message using Kotlin Flow. The bridge between Compose State and coroutines.

Kotlin — HomeScreenTests.kt (JetNews) 
@Test
fun postsContainError_snackbarShown() {
    val snackbarHostState = SnackbarHostState()

    composeTestRule.setContent {
        JetnewsTheme {
            HomeFeedScreen(
                uiState = HomeUiState.NoPosts(
                    isLoading = false,
                    errorMessages = listOf(ErrorMessage(0L, R.string.load_error)),
                    searchInput = "",
                ),
                snackbarHostState = snackbarHostState,
                // ... other params
            )
        }
    }

    runBlocking {
        // snapshotFlow converts Compose State → Kotlin Flow
        val actualSnackbarText = snapshotFlow { snackbarHostState.currentSnackbarData }
            .filterNotNull()
            .first()           // suspend until first non-null value
            .visuals.message
        assertEquals(expectedText, actualSnackbarText)
    }
}
snapshotFlow re-emits whenever any Compose State it reads changes — it's the bridge from Compose's reactive state system to Kotlin coroutines. Perfect for asserting composable side-effects like showing a snackbar or triggering animation.
06

Faking Dependencies for UI Tests

Two patterns: full DI replacement via TestAppContainer (JetNews), or passing state inline (Jetchat).

TestAppContainer pattern — JetNews

Kotlin — TestAppContainer.kt 
class TestAppContainer(context: Context) : AppContainer {
    override val postsRepository: PostsRepository by lazy {
        BlockingFakePostsRepository()  // synchronous — no network delay
    }
    override val interestsRepository: InterestsRepository by lazy {
        FakeInterestsRepository()
    }
}

// Extension to launch the whole app with fakes injected
fun ComposeContentTestRule.launchJetNewsApp(context: Context) {
    setContent {
        JetnewsApp(
            appContainer = TestAppContainer(context),
            isBackEnabled = true,
            initialBackStack = listOf(HomeKey),
        )
    }
}

// In every test:
@Before
fun setUp() {
    composeTestRule.launchJetNewsApp(ApplicationProvider.getApplicationContext())
}
Blocking vs non-blocking fakes: BlockingFakePostsRepository returns data synchronously (no delay(800)), unlike FakePostsRepository which simulates network lag. Synchronous fakes prevent flakiness caused by timing differences.

Inline fake data — Jetchat

For tests without DI, pass state directly to the composable:

Kotlin — ConversationTest.kt 
@Before
fun setUp() {
    composeTestRule.setContent {
        JetchatTheme {
            ConversationContent(
                uiState = conversationTestUiState,  // inline fake — no DI
                navigateToProfile = { },
                onNavIconPressed = { },
            )
        }
    }
}

// Build test data inline — double the messages so scroll tests make sense on tablets
private val conversationTestUiState = ConversationUiState(
    initialMessages = exampleUiState.messages + exampleUiState.messages,
    channelName = "#composers",
    channelMembers = 42,
)

Unit Tests for Business Logic — Jetcaster

The only app with proper unit tests. Shows how to test UseCases with coroutines using runTest and test repositories backed by MutableStateFlow.

runTest for coroutine-based logic

Kotlin — PodcastCategoryFilterUseCaseTest.kt 
class PodcastCategoryFilterUseCaseTest {
    private val categoriesStore = TestCategoryStore()
    val useCase = PodcastCategoryFilterUseCase(categoryStore = categoriesStore)

    @Test
    fun whenCategoryNull_emptyFlow() = runTest {
        val resultFlow = useCase(null)

        // Emit data into fake store AFTER collecting the flow
        categoriesStore.setEpisodesFromPodcast(testCategory.id, testEpisodeToPodcast)
        categoriesStore.setPodcastsInCategory(testCategory.id, testPodcasts)

        val result = resultFlow.first()
        assertTrue(result.topPodcasts.isEmpty())
        assertTrue(result.episodes.isEmpty())
    }

    @Test
    fun whenCategoryInfoNotNull_verifyLimitFlow() = runTest {
        val resultFlow = useCase(testCategory.asExternalModel())

        // 8x episodes → UseCase must cap at 20 max
        categoriesStore.setEpisodesFromPodcast(testCategory.id, List(8) { testEpisodeToPodcast }.flatten())
        categoriesStore.setPodcastsInCategory(testCategory.id, List(4) { testPodcasts }.flatten())

        val result = resultFlow.first()
        assertEquals(20, result.episodes.size)
        assertEquals(10, result.topPodcasts.size)
    }
}
runTest vs runBlocking: runTest uses a TestCoroutineScheduler — virtual time advances instantly so no real delays in tests. runBlocking is fine for UI tests but blocks a real thread; runTest is correct for testing coroutine-based production code.

MutableStateFlow test repositories

Kotlin — TestPodcastStore.kt 
class TestPodcastStore : PodcastStore {
    private val podcastFlow = MutableStateFlow<List<Podcast>>(listOf())
    private val followedPodcasts = mutableSetOf<String>()

    override fun podcastsSortedByLastEpisode(limit: Int): Flow<List<PodcastWithExtraInfo>> =
        podcastFlow.map { podcasts ->
            podcasts.map { p ->
                PodcastWithExtraInfo().apply {
                    podcast = p
                    isFollowed = followedPodcasts.contains(p.uri)
                }
            }
        }

    override suspend fun addPodcast(podcast: Podcast) = podcastFlow.update { it + podcast }
    override suspend fun togglePodcastFollowed(uri: String) { /* toggle logic */ }
}

Why MutableStateFlow in test repos?

  • Test controls exactly what data the UseCase sees
  • Flow-based — matches production interface exactly
  • Thread-safe — update {} is atomic
  • No threading issues or synchronization needed

08

Navigation Testing

Testing Fragment + Compose navigation via NavController ID checks and custom SemanticsMatcher.

Kotlin — NavigationTest.kt (Jetchat) 
@Test
fun profileScreen_back_conversationScreen() {
    val navController = getNavController()
    navigateToProfile("Taylor Brooks")
    assertEquals(navController.currentDestination?.id, R.id.nav_profile)

    Espresso.pressBack()  // works for Fragment navigation

    assertEquals(navController.currentDestination?.id, R.id.nav_home)
}

// Custom semantic matcher — only match items inside the nav drawer
private fun isInDrawer() = hasAnyAncestor(isDrawer())
private fun isDrawer() = SemanticsMatcher.expectValue(
    SemanticsProperties.PaneTitle,
    activity.getString(androidx.compose.ui.R.string.navigation_menu),
)

// Regression test — back stack must not accumulate after multiple nav sequences
@Test
fun drawer_conversationScreen_backstackPopUp() {
    navigateToProfile("Ali Conors (you)")
    navigateToHome()
    navigateToProfile("Taylor Brooks")
    navigateToHome()
    assertEquals(getNavController().currentDestination?.id, R.id.nav_home)
}
SemanticsMatcher lets you build custom predicates over any semantic property. Here it filters clicks to only items inside the navigation drawer, preventing false matches against nodes with the same text elsewhere in the tree.
09

State Persists Through Recomposition

Changing a MutableStateFlow in the test triggers a full recomposition. If rememberLazyListState wasn't remembered properly, scroll position would reset and the test would catch it.

Kotlin — ConversationTest.kt (Jetchat) 
private val themeIsDark = MutableStateFlow(false)

@Before
fun setUp() {
    composeTestRule.setContent {
        JetchatTheme(isDarkTheme = themeIsDark.collectAsStateWithLifecycle(false).value) {
            ConversationContent(uiState = conversationTestUiState, ...)
        }
    }
}

@Test
fun changeTheme_scrollIsPersisted() {
    // Scroll up to make "Jump to Bottom" appear
    composeTestRule.onNodeWithTag(ConversationTestTag).performTouchInput {
        swipe(start = center, end = Offset(center.x, center.y + 500), durationMillis = 200)
    }
    findJumpToBottom().assertIsDisplayed()

    // Trigger full recomposition by changing theme
    themeIsDark.value = true

    // Scroll position must survive — if LazyListState lost, button disappears
    findJumpToBottom().assertIsDisplayed()
}

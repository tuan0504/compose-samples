Color Tokens

Named, reusable color values that form the palette of the design system.

JetNews — M3 Slot Model (28 named roles)

Every color is named after its role, not its visual appearance. The M3 slot model decouples the name from the actual hue so it can swap between light/dark without logic changes.

Kotlin 
// Color.kt
val Red700 = Color(0xFFBF0031)

// All 28 M3 roles defined:
val md_theme_light_primary            = Red700
val md_theme_light_onPrimary          = Color(0xFFFFFFFF)
val md_theme_light_primaryContainer   = Color(0xFFFFDAD9)
val md_theme_light_onPrimaryContainer = Color(0xFF40000A)
// ... secondary, tertiary, error, background, surface families
The M3 Role System
  • primary / onPrimary — main brand color + text on top of it
  • primaryContainer / onPrimaryContainer — tinted container + content inside
  • surface / onSurface — card and sheet backgrounds + content
  • background / onBackground — screen background + content
  • error / onError / errorContainer / onErrorContainer — error states

Kotlin — JetsnackColors semantic mapping 
data class JetsnackColors(
    val gradient6_1: List<Color>,        // 6-stop gradient for hero surfaces
    val gradient3_1: List<Color>,        // 3-stop gradient for cards
    val gradient2_1: List<Color>,        // 2-stop gradient for buttons
    val brand: Color,                   // primary brand color
    val interactivePrimary: List<Color>, // gradient list for buttons
    val textPrimary: Color,
    val textInteractive: Color,
    val tornado1: List<Color>,
    val isDark: Boolean
)
Why Ramps?

An 11-step ramp gives a full tonal range from dark to light for a single hue — identical to how M3's internal tonal palettes work. Jetsnack hand-picks steps from these ramps to assemble gradients, giving precise control over every shade.

Spacing Tokens

Named layout constants — only Jetcaster formalizes these in the shared module.

Kotlin — core/designsystem/theme/Keylines.kt 
val Keyline1 = 16.dp   // standard content margin
Why Name Spacing?

This single named constant is referenced across all screens (mobile, TV, Wear) for consistent left/right padding. Other apps use 16.dp inline — Jetcaster formalizes it because a value change in one place must propagate simultaneously to three targets.

Component Library

How each app wraps (or doesn't wrap) Compose primitives into themed, reusable components.

2.1 JetNews — Thin Layer (2 wrappers)

components/
  • AppNavRail.kt — NavigationRail with Jetnews-specific items
  • JetnewsSnackbarHost.kt — SnackbarHost with branded positioning
Pattern

Import M3 Card, TopAppBar, Button directly. Pass MaterialTheme.colorScheme.* as parameters when needed. No custom component class. Use this when Material 3 components fit your design exactly — zero abstraction overhead.

2.2 Jetchat — Scaffolding Layer (6 wrappers)

components/
  • JetchatAppBar.kt — CenterAlignedTopAppBar with chat-specific actions
  • JetchatDrawer.kt — ModalNavigationDrawer with channel list
  • JetchatScaffold.kt — Scaffold wrapper with chat layout logic
  • JetchatIcon.kt — Icon with branded tinting
  • AnimatingFabContent.kt — FAB with text-expansion animation
  • BaseLineHeightModifier.kt — Custom Modifier for text baseline alignment
Pattern

Wrap M3 scaffold components to encapsulate layout decisions. The app bar knows about chat-specific actions; the scaffold knows about chat-specific slot positions. Good for apps where M3 structure is right but slot content is custom.

2.3 Jetsnack — Full Custom Library (11 wrappers)

Every M3 component Jetsnack uses is wrapped and re-skinned to use JetsnackTheme.colors instead of MaterialTheme.colorScheme.

components/
  • Button.kt — JetsnackButton (gradient background, pill shape)
  • Card.kt — SnackCollection card layout
  • Divider.kt — JetsnackDivider (uses JetsnackTheme.colors.uiBorder)
  • Gradient.kt — Modifier extensions: diagonalGradientTint, offsetGradientBackground, fadeInDiagonalGradientBorder
  • GradientTintedIconButton.kt — Icon button with diagonal gradient tint
  • Grid.kt — Custom staggered grid layout
  • QuantitySelector.kt — +/- quantity control
  • Scaffold.kt — JetsnackScaffold (custom bottom bar slot)
  • Snackbar.kt — JetsnackSnackbar (branded notification)
  • Snacks.kt — SnackItem, SnackCollection composables
  • Surface.kt — JetsnackSurface (consumes JetsnackTheme colors)
Kotlin — JetsnackButton (gradient — impossible with M3 Button) 
@Composable
fun JetsnackButton(
    onClick: () -> Unit,
    backgroundGradient: List<Color> = JetsnackTheme.colors.interactivePrimary,
    contentColor: Color            = JetsnackTheme.colors.textInteractive,
    content: @Composable RowScope.() -> Unit,
) {
    JetsnackSurface(
        modifier = Modifier
            .background(Brush.horizontalGradient(colors = backgroundGradient))
            .clip(ButtonShape),   // ButtonShape = RoundedCornerShape(50%)
    ) { /* ... */ }
}
Kotlin — Gradient.kt Modifier library 
// Diagonal gradient tint over any content:
Modifier.diagonalGradientTint(colors = JetsnackTheme.colors.tornado1, blendMode = BlendMode.Darken)

// Scroll-aware tiling gradient:
Modifier.offsetGradientBackground(colors = gradient, width = { size.width }, offset = { scroll.toFloat() })

// Animated gradient border (fades in/out with selection state):
Modifier.fadeInDiagonalGradientBorder(showBorder = selected, colors = gradient, shape = shape)

2.4 Jetcaster — Shared Multi-Platform Components

core/designsystem/component/ contains components shared across mobile, TV, and Wear — a single source of truth for image loading, placeholders and HTML rendering.

core/designsystem/component/
  • PodcastImage.kt — Coil async image with loading/error states + shimmer placeholder
  • ImageBackground.kt — Full-bleed background image with gradient overlay
  • HtmlTextContainer.kt — Renders HTML episode descriptions as styled Compose text
  • thumbnailPlaceholder.kt — Animated shimmer brush for loading placeholders
Kotlin — PodcastImage (well-structured shared component) 
@Composable
fun PodcastImage(
    podcastImageUrl: String,
    contentDescription: String?,
    modifier: Modifier = Modifier,
    placeholderBrush: Brush = thumbnailPlaceholderDefaultBrush(),
) {
    // Preview mode: solid color box (no network call)
    if (LocalInspectionMode.current) {
        Box(modifier = modifier.background(MaterialTheme.colorScheme.primary))
        return
    }
    // Runtime: Coil async load → loading/error → final image
}

Token Access Patterns

How components consume tokens determines how easy the system is to theme and test.

Simplest

MaterialTheme Direct

Used by: JetNews, Reply, Jetchat
Kotlin 
@Composable
fun ArticleCard() {
    Card(
        colors = CardDefaults.cardColors(
            containerColor = MaterialTheme.colorScheme.surfaceVariant,
        )
    ) {
        Text(
            style = MaterialTheme.typography.bodyMedium,
            color = MaterialTheme.colorScheme.onSurfaceVariant,
        )
    }
}
✅ Pros
  • Zero extra code
  • Works with dynamic color automatically
  • Works with system dark mode
❌ Cons
  • Can't add tokens M3 doesn't have
  • No sleepDeep color slot in M3
Extended M3

CompositionLocal Extra Layer

Used by: JetLagged
Kotlin 
// 1. Define extra tokens
data class JetLaggedExtraColors(val sleepDeep: Color = Color(0xFFFC424A))

// 2. Provide at theme root
val LocalExtraColors = staticCompositionLocalOf { JetLaggedExtraColors() }

@Composable
fun JetLaggedTheme(content: @Composable () -> Unit) {
    CompositionLocalProvider(LocalExtraColors provides JetLaggedExtraColors()) {
        MaterialTheme(content = content)
    }
}

// 3. Consume anywhere:
val colors = LocalExtraColors.current
Box(modifier = Modifier.background(colors.sleepDeep))
✅ Pros
  • Extends M3 cleanly without replacing it
  • Easy to add domain-specific tokens
  • Material You still works
❌ Cons
  • Must remember to read LocalExtraColors.current
  • Easy to forget in deeply nested composables
Full Custom

Custom Theme Object

Used by: Jetsnack
Kotlin 
// Theme object — type-safe access to all tokens:
object JetsnackTheme {
    val colors: JetsnackColors
        @Composable get() = LocalJetsnackColors.current
    val typography: Typography
        @Composable get() = MaterialTheme.typography
}

// Components always use JetsnackTheme, never MaterialTheme.colorScheme:
val gradient = JetsnackTheme.colors.gradient6_1
val brand    = JetsnackTheme.colors.brand

// debugColors() — magenta sentinel catches M3 leakage in dev builds:
fun debugColors() = JetsnackColors(brand = Color.Magenta, ...)
✅ Pros
  • Type-safe — all tokens discoverable via IDE autocomplete
  • debugColors() enforces no M3 leakage
  • Complete design system isolation
❌ Cons
  • More boilerplate upfront
  • Cannot use Material You dynamic color
  • Must re-implement everything M3 provides for free

Anti-Patterns to Avoid

Six concrete mistakes and how to fix them.

1. Hardcoding colors inline

Kotlin 
// ❌ BAD — hardcoded, won't respond to dark mode
Text(color = Color(0xFF333333))

// ✅ GOOD — responds to theme automatically
Text(color = MaterialTheme.colorScheme.onSurface)

2. Using Color.Unspecified as a sentinel

Jetsnack's Solution

Jetsnack uses debugColors() with Color.Magenta — any composable that doesn't explicitly set a color gets an obvious magenta tint during development, making unthemed components immediately visible.

3. Mixing M3 colors with your custom system

Rule

Once you've adopted a custom system like Jetsnack's, never mix MaterialTheme.colorScheme.primary with JetsnackTheme.colors.brand. Pick one system and enforce it — debugColors() is the enforcement mechanism.

4. Ignoring the onX contract

Kotlin 
// ❌ BAD — onSurface has no guaranteed contrast against primary
Box(modifier = Modifier.background(MaterialTheme.colorScheme.primary)) {
    Text(color = MaterialTheme.colorScheme.onSurface)
}

// ✅ GOOD — onPrimary is guaranteed contrast against primary
Box(modifier = Modifier.background(MaterialTheme.colorScheme.primary)) {
    Text(color = MaterialTheme.colorScheme.onPrimary)
}

5. Skipping LocalInspectionMode in shared components

Kotlin — correct pattern from PodcastImage.kt 
@Composable
fun PodcastImage(...) {
    // Short-circuit in Compose Preview — no network call, no crash
    if (LocalInspectionMode.current) {
        Box(modifier = modifier.background(MaterialTheme.colorScheme.primary))
        return
    }
    // Real image loading only at runtime
}

6. Defining spacing as raw dp everywhere

Rule

If the same spacing value is referenced across more than one module or form factor, name it (val Keyline1 = 16.dp). A find-and-replace across multiple targets is error-prone; a named token is a single change.

Summary

The spectrum from zero abstraction to full custom — and how to pick your position.

🎯
Brand distance from Material
Close → stay on M3 (Pattern A). Diverged → wrap or replace (Pattern C).
📱
Number of targets
One app → colocate tokens in ui/theme. Multiple targets → extract to a Gradle module (Pattern D).
🔑
Extra tokens needed?
None → MaterialTheme is enough. Domain-specific → add CompositionLocal (Pattern B).
♿
Accessibility tiers
Reply's UiModeManager.contrast detection is the reference implementation for contrast-tier support.
Starting Point

Start with Pattern A and add complexity only when you hit a concrete wall. Most production apps that follow Material guidelines never need to go beyond Pattern B.
